# 教程 3：助手首次配置与日常使用

**前提**：已经按教程 1、2 完成准备，Proxy Manager 正在运行，并且你手上有：
- 预期出口 IP（从 Bright Data 控制台抄）
- 代理名称（zone）
- Proxy Manager 1.679.135 安装包（放在“下载”“桌面”或“文档”文件夹里，改过文件名也能找到）

## 一、首次配置（只做一次）

打开助手，点 **首次配置向导**。

### 1. 只需要手动填两项

| 项目 | 填什么 |
|---|---|
| 独立预期出口 IP | 教程 1 记下的 ISP IP。要从 Bright Data 控制台抄，**不要**把助手检测出来的 IP 当成预期 IP |
| 独立预期区域 | 教程 1 里的代理名称（zone 名），和 Proxy Manager 端口列表里显示的名字一字不差 |

其余几项已经预先填好，一般不用改：

| 项目 | 默认值 |
|---|---|
| 出口检测服务 HTTPS 地址 | `https://api.ipify.org`（要换的话：返回纯 IP 或 JSON `{"ip": "..."}` 的网址都可以，不能带 `?` 参数） |
| 目标映射要求 | 固定为“明确不需要目标映射”，不能改 |
| Claude 网页地址 | `https://claude.ai/` |

### 2. 点“一键查找并填入”

助手会自动做这几件事（最多约半分钟）：

1. 找到正在运行的 Proxy Manager 程序和它的安装文件夹；
2. 找出管理端口（如 22999）和代理端口（如 24000）。有多个代理端口时，优先选代理名称和你填的区域名一致的那个；
3. 在“下载”“桌面”“文档”里找 1.679.135 安装包，并自动打开 **核验管理器安装来源**，填好安装包和安装文件夹。

核验通过后，点 **保存本机配置**。

> 没有全部找到时，窗口里会写明缺哪一项、怎么处理。处理后再点一次；也可以像以前一样手动操作：**查找并选择端口**、**选择安装包并核验**。

### 3. 网页端才需要：选专用 Chrome

点 **选择已有快捷方式**，选你给 Claude 专用的那个 Chrome 快捷方式，核对程序和配置目录。

> 专用 Chrome：建议给 Claude 单独建一个 Chrome 用户（单独的快捷方式和用户数据目录），并让它通过 Proxy Manager 的代理端口上网。具体方法可以参考 Bright Data 官方的[浏览器扩展说明](https://docs.brightdata.com/proxy-networks/browser-extension/quickstart)。

## 二、环境体检（推荐每次换环境后做一次）

主窗口或配置向导里点 **环境体检**。它只读取、不修改任何东西，会逐项告诉你哪里有问题、该怎么改：

| 检查内容 | 说明 |
|---|---|
| Clash、Proxy Manager 是否在运行 | 没开就提示先打开 |
| Proxy Manager 版本 | 必须是 1.679.135，自动升级过会提示重装 |
| 保存的管理器基准 | 和这台电脑上的 Proxy Manager 是否对得上 |
| 管理端口、代理端口 | 一个个端口单独检查是否在工作、代理名称是否和你填的区域名一致 |
| 代理类型 | 是否为 ISP（固定 IP） |
| Windows 系统代理 | 系统代理不能直接指向 Proxy Manager 的端口 |
| 经代理上网、Claude 看到的 IP | 经代理端口请求出口检测服务和 Claude 检查页，和预期 IP 对比 |
| 三个出口是否一致 | Claude 检查页、Cloudflare（one.one.one.one）、国内 IP 查询站三处看到的出口是否相同 |
| 电脑时间 | 和 Claude 服务器相差不超过 5 分钟 |
| 时区和语言 | 电脑时区、显示语言、区域格式是否和出口所在地相符（只提醒，不阻止使用） |
| Claude 桌面端 | 是否已安装、是否开着 |

体检窗口里还有：**重新体检**、**复制体检报告**、**打开时区设置**、**打开语言设置**。时区和语言请你自己在 Windows 设置里改，助手不会替你改。

> 有些 Windows 版本的端口列表会漏掉 Proxy Manager 的端口。这时助手会直接连一下这个端口，再确认接这个连接的是不是 Proxy Manager，体检里会出现一条“系统端口列表”提醒，不影响使用。

### 一键修复

体检发现下面两类问题时，**一键修复** 按钮会亮起，点之前会先列出要做的每一步，等你确认：

| 问题 | 一键修复会做什么 |
|---|---|
| Proxy Manager 没在运行、端口没在工作、管理接口没回应 | 先确认 Claude 桌面端已经关闭（开着就停下，**不会强制关闭 Claude**）→ 只结束安装文件夹里那一个 Proxy Manager → 重新打开它，最多等 90 秒让端口恢复 → 自动重新体检 |
| 还没保存管理器基准，或基准对不上 | 打开配置向导，自动“一键查找并填入”并核验，最后由你点“保存本机配置” |

Proxy Manager 版本不对时不会用“重启”来修，要用 1.679.135 安装包重新安装。

## 三、用桌面端

1. 主窗口点 **查找桌面端**，选中找到的 Claude 桌面端。
2. 如果 Claude 桌面端已经开着，先**自己正常退出**它。
3. 点 **重新检测**，等各项检查都显示通过。
4. 点 **启动桌面端**，发一条消息，确认能正常收发。

检测结果只在 60 秒内有效，超时后要重新检测才能启动。

## 四、用网页端（带持续监测）

1. 点 **选择本次专用 Chrome**，选中刚才配置的那个专用 Chrome。
2. 点 **重新检测**，检测通过后点 **打开网页端**。
3. 点 **开始监测**，助手会定时核对这个 Chrome 的出口：
   - 出口一旦异常，助手会立刻断开这个 Chrome 的网络，报告里会写明原因；
   - 先排查原因（比如 Proxy Manager 是不是关了、IP 有没有变），再点 **手动复检恢复**。
4. 不用了就点 **停止监测**。

## 五、自己再核对一次：Claude 检查页（很重要）

在专用 Chrome 里打开 <https://claude.ai/cdn-cgi/trace>，这是 Claude 自己的检查页，显示的是 **Claude 实际看到的你**：

| 看哪一行 | 应该是 |
|---|---|
| `ip=` | 你的预期出口 IP |
| `loc=` | 出口所在国家或地区的两位代码（如 `US`） |

`ip=` 不是预期 IP 时，先不要登录 Claude，回到 Proxy Manager 和浏览器的代理设置排查。

> 第三方检测网站上的“Cloudflare 出口 IP”有时是浏览器直接去查 1.1.1.1，不一定走专用 Chrome 的代理，显示不一致不代表 Claude 的连接有问题。以上面 Claude 检查页的 `ip=` 为准。

## 六、报告

- **复制报告 / 导出报告**：默认隐藏完整 IP；勾选“报告包含完整 IP”后才会显示完整 IP。
- **查看历史**：保留最近 10 次检测的报告，关闭助手后会清空。

## 避坑提醒

- 任何输入框都**不要**填账号、密码、令牌或聊天内容。配置是明文保存在本机的。
- 换电脑或重装系统后，要按这台电脑的实际情况重新配置（点“一键查找并填入”最快）。不要直接复制别的电脑的配置文件。
- Proxy Manager 弹出“是否下载新版本”“退出时安装 / 立即安装”时，**都不要点安装**。升级后版本不再是 1.679.135，检测会一直不通过。
